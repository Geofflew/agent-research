# Per-task agent pricing

Definition: pricing agent work by completed action or accepted outcome instead of by seat, entity, or module.

Sub-question: roles-and-economics

Related concepts: [[adoption-ladder]], [[preparer-and-reviewer-roles]], [[validation-harness]]

Evidence:
- Close software commonly charges by entity and module; reconciliation automation can be priced by accounts or reconciliations [aprice-vendr-floqast-pricing-2026].
- Outside finance: Salesforce 20 Flex Credits/action [buyer-salesforce-agentforce-pricing]; Intercom $0.99/outcome, refund on reopen [buyer-intercom-fin-per-outcome]; Zendesk automated resolutions + seats [buyer-zendesk-automated-resolutions]; Workday meters completed actions, CFO frame = cost avoidance, headcount [buyer-workday-usage-based-ai-pricing].

What the thesis says: C5 — close platform prices per accepted task by end 2028; refund on reviewer rejection or period reopen; buyer moves controller -> CFO; invoice doubles as per-class error-rate report.

Open questions:
- Does a refund-on-rejection unit give reviewers an incentive problem (vendor pressure to accept)?
- Does any close vendor already meter agent tasks (BlackLine, FloQast, Workday Financial Close Agent)?
