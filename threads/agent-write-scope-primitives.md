# Which outside-finance permission primitives transfer to agent posting, and which fail for a ledger?

Status: live
Opened: session 0006A (from retired C6)
Yield: 3.38 (0007A C10 +0.81; 0008C C10 experience +0.88)
Touches: C10, C24, C2, C23
Sources: [mcp-authorization-spec], [spiffe-standard], [cedar-policy-readme], [ap2-docs-mandates], [agentic-commerce-protocol-readme], [replit-database-deletion-incident], [autoctl-ms-d365-journal-workflow-thresholds], [erpmcp-ms-business-central-mcp-configure], [agentperm-oracle-agent-studio-tool-approval], [claude-code-permissions]

What we know so far: Outside finance the pieces exist separately. MCP binds a token to one server, SPIFFE gives a workload a signed identity, Cedar keeps policy outside application code, and the agentic commerce delegate-payment allowance bounds a token by amount, currency, and expiry. None of them expresses "this agent may post this class of entry to these accounts in this open period". Two remedies offered for agent incidents fail for a ledger: Replit's dev/prod separation has no equivalent because there is one production ledger, and an audit trail records a posting without stopping it. Dynamics 365 journal workflows already route entries above a total debit amount to an approver, which is where C10 now puts journal amounts, while Business Central's MCP server grants posting per API object with no amount limit, and Oracle's per-tool approval bounds which tool runs, not how much it posts.

What it would take to become a claim again: a shipped ERP release note scoping an agent principal by account, journal type, or period (not amount alone), or an incident where an agent posted to a production ledger and the remedy is documented.

Open sub-questions:
- Can an agent principal get a lower journal-workflow threshold than the human whose role it inherits?
- Does any policy engine (Cedar, OPA) ship with an accounting-period or account-class attribute in a finance product?
