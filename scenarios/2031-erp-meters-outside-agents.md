# By 2031 ERP vendors meter every write an outside agent makes through their protocol servers, so the general-purpose agent close becomes uneconomic and the close stays with ERP-native agents and the close platforms that pay the meter

Year: 2031
Status: live
Contradicts: 2031-the-accounting-firm-runs-the-small-company-close. There a CPA firm's agents run small companies' closes across many clients' ledgers and absorb any meter in a fixed fee; here the ERP prices outside writes so only its own agents and high-volume close platforms can afford them, and the company, not a firm, buys the close.
Depends on:
- C10 (ERP protocol servers scope an outside agent by role and record type rather than amount or period): the ERP already identifies every outside call by role and record type, which is what lets it meter by record type; if outside agents reached the ledger some other way, there would be nothing to meter.
- C23 (the agent reading outside documents is kept from payee details and payment release, because injection has no reliable prevention): the vendor justifies throttling outside writes as a security control; if outside agents carried no adversarial risk, that argument would not hold.
- C33 (the agent signs the preparer's checklist line with output attached): an outside agent's close needs many writes per task, posting, attaching, and signing, so a per-write price falls hardest on that work; if sign-offs lived outside the ERP, the meter would not reach them.
- C39 (which write actions an ERP's protocol server gives outside agents is the ERP vendor's choice, which no rule constrains as payment rules constrain banks): metering is that choice exercised through price rather than permission; if a regulator constrained ERP write access the way payment rules constrain banks, the vendor could not price outside writes above its own agents' cost.
Clocks: Workday already sells AI as Flex Credits, an annual bulk purchase that charges for work AI completes, and NetSuite meters AI Units after each task runs, so both have metering in place; Business Central's and Workday's protocol endpoints were documented in 2026, and contract renewals on one- to three-year terms reprice outside-agent access from the 2027 to 2029 renewals; SAP's old ERP leaves mainstream maintenance at the end of 2027, the point at which mid-market buyers compare the metered price of outside writes across replacement ERPs.
Yield: 0.0

In 2031 a mid-market company that tried to run its close with the general-purpose agent its other departments use has moved back to its ERP's own close agents. The protocol server still accepts outside agents, but since the 2028 renewal each write, a posted journal, an attached file, a status change, draws credits from the pool the ERP's own agents use, so an outside agent that posts, attaches, and signs item by item costs more than the native agent, which freezes rules inside the ledger and makes a fraction of the calls (the size of the gap is illustrative). Close platforms with thousands of customers negotiate volume rates and pass them on, so they survive; the general agent with purchased skills does not, except on the few ERPs that kept outside writes free. What is bought and sold is access to the ledger's write path, priced per record type, and the ERP vendors' finance revenue grows from the meter rather than from seats.

Mechanism: Workday and NetSuite already meter AI by usage, and ERP protocol servers already identify every outside call by role and record type (C10), so a per-write price needs no new infrastructure. Outside agents read adversarial documents (C23), which gives the ERP vendor a security reason to throttle and price their writes that customers and auditors accept. At the 2027 to 2029 renewals the vendors extend metering from their own agents to outside agents' writes. A general agent doing the close item by item, with an attachment and a sign-off per checklist line (C33), makes many more writes than a native agent running frozen rules inside the ledger, and nothing stops the vendor pricing them differently (C39), so the meter moves the cost advantage to native agents. Buyers replacing SAP's old ERP from 2027 compare meters, and the open-and-free ERPs become a niche.

The controller stops choosing skills for a general agent and goes back to configuring the ERP's native agents, watching a credit console that shows which close tasks consume the most writes. The close platform's CFO negotiates a write rate with each ERP vendor, which becomes the platform's largest cost. The CIO decides which outside agents may write at all, on cost as much as risk.

What would settle it: an ERP price list charging outside agents per write through its protocol server; a close platform disclosing ERP access fees as a cost line.

Signposts: an ERP vendor announcing metered pricing for protocol-server writes at or after the 2027 renewals; failing signpost, by 2029 the major ERPs keep outside writes free under existing licenses, which would leave the general-agent close economical.
